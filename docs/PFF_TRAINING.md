# PFF raw-observation joint-head experiment

The experiment is isolated from production. The frozen v1.5 model, decoding settings and submission remain unchanged. The candidate is one replacement joint H/A/D residual head trained for eight epochs with seed 20261101, using the fixed PFF training fixtures plus the seven exposed Sportec fixtures. Development selection and any final evaluation are separate from training; no automatic promotion is implemented here.

## Observation/reference separation

The delivered PFF Tracking Data Specification v2.2 explicitly describes `ballsSmoothed` as event-derived: the ball is placed at the labelled carrier and interpolated between events. Those fields cannot be used to independently recover the same possession events. `tools/pff_adapter.py` ignores **all** smoothed locations and embedded game/possession events during inference. It uses only original raw player/ball coordinates with `visibility == VISIBLE`; estimated or ambiguous ball locations remain missing. Team-specific jersey numbers identify geometry slots without using event ownership.

The PFF coordinates are centred metres. The adapter normalizes pitch coordinates, reverses the y axis consistently for players and ball, and derives speeds within periods. It collapses duplicated event-associated frames only when their retained observations agree. Metadata/frame identities and ordering are checked. Repeated `gameRefId` headers may be absent after the first row; at least one matching header is required and any conflicting identity fails.

Native 29.97-Hz observations are sampled onto a fixed 25-Hz video-clock grid, using the nearest source observation within half a native frame. No missing native frame is interpolated by the adapter. The downstream frozen production feature extractor retains its existing limited interpolation rules, equally for baseline and candidate. A synthetic X frame separates periods, including extra time, so official spell diagnostics cannot merge periods. Native frame-number and video-time consistency is audited; a disagreement beyond one native frame fails.

`read_references` is a separate entry point that reads the current Event Data JSON, not the older embedded annotations. It deduplicates by game-event ID plus normalized event kind, because native files reuse OTB identifiers for distinct later FOUL records; conflicting copies of the same ID and kind still fail. It uses video `startTime` rather than the game clock, starts each period unknown, and carries the controlled team from explicit OTB/kickoff events. OUT/END begin D even when their end time is absent. G, substitutions and player-on/off events do not imply restarts. Unknown event kinds, missing video and initial-non-event annotations reset certainty; their explicit uncertainty intervals remain X. Explicit null uncertainty flags also reset certainty until another known state, including on otherwise ignored FOUL records. Subordinate possession-event actions, including their `nonEvent` fields, are not ownership supervision. Missing event rows never become negative labels or D by themselves. Missing source frames and synthetic period separators remain X.

These carried labels are **provider event-derived silver**, not independently reviewed dense human truth. The package does not certify whistle completeness, precise onset/restart timing or controlled-possession equivalence to the challenge. Their presence alone cannot authorize promotion.

## Training and comparison API

- `pff_adapter.read_observations(metadata_path, tracking_path)` returns `Tracking, blocks, pitch, alignment` without reconstructing references.
- `pff_adapter.read_references(event_path, alignment)` returns labels and label-support/provenance counts.
- `pff_training.prepare_cache(tracking, blocks, pitch, fps)` returns observation features, frozen upstream probabilities, v1.5 labels and probabilities. It accepts no reference/event argument.
- `pff_training.predict_cache(item, model)` reuses the same observations for a paired candidate comparison; reference payloads added to the item have no effect.
- `pff_training.fit_candidate(items, training_matches=..., held_out_matches=..., protocol_sha256=...)` validates exact whole-fixture membership and replaces only the joint residual head in a copy of the baseline. It never writes the production artifact. Pass a generator of full-rate items to bound memory.

At 5 Hz, training weights emphasize short possessions and nearby state boundaries, then normalize each fixture to equal total sampled weight. Unknown frames have zero weight. The existing deterministic CPU trainer optimizes the same joint objective and architecture as v1.5. Its minibatch normalization means equal total fixture weights do not imply exactly equal optimization influence in every batch. Scaling is learned from positive-weight training rows only. Upstream control/dead/temporal heads and decoder remain fixed.

## Engineering evidence and pilot

Sixteen adapter tests cover raw/reference separation, event-derived-smoothed exclusion, estimated/multiple-ball abstention, native duplicates, timeline gaps, coordinate transforms, period isolation, ID validation, state carry, nullable uncertainty, reused cross-kind event IDs, invalid flag rejection, reference conflicts and exact equivalence of compact transient records. Eight training tests cover whole-fixture exclusion, unknown-weight handling, equal sampled fixture mass, protocol requirements, unchanged upstream weights and exact synthetic parity with the production v1.5 inference path.

The first fitting attempt stopped during training-reference preparation, before candidate fitting or held-out reference access. A training-only audit of 88,975 event rows found 13 rows with both uncertainty flags null, all FOUL records across nine fixtures. These represent 12 distinct FOUL events sharing IDs with earlier OTB events, plus one repeated FOUL row. No missing uncertainty keys or other duplicate field disagreements appeared in the 40 training files. The correction preserves distinct event kinds and maps null certainty to X. All 40 training references then reconstructed successfully: 1,702,237 H, 1,617,416 A, 2,504,392 D and 300,814 X grid rows. These are reference support counts, not evaluation results. The prior adapter was preserved with the aborted run; AST comparison confirms that only `references()` changed, allowing separately authenticated observation-cache migration without altering inputs. The local audit is recorded in `runs/pff-access/training-reference-schema-validation.json`.

Training-only pilot 3812 has 185,746 native rows, including 889 duplicated event-associated frames. Its raw-visible ball coverage is about 33.06% on the resampled observation grid; the maximum checked native/video clock discrepancy is below one microsecond. These are intake diagnostics, not model performance. Root campaign reports record actual fitting, development scores and any one-shot final audit separately. The pilot was assigned to training before its labels were inspected.

Before any fitting or scoring, transient player records were compacted into lossless little-endian integer/float64 bytes to reduce RAM. Re-reading the complete pilot reproduced identical observations, alignment, control/dead features, upstream probabilities and 154,201 baseline labels. The verification process used about 756 MiB peak working memory and 86 seconds on this machine. A separate actual-pilot check reproduced production inference labels and probabilities exactly. These engineering checks consumed no held-out reference labels and changed no thresholds or model policy.

Official parser context: [Kloppy PFF loader](https://kloppy.pysport.org/reference/providers/pff/) exposes all-frame loading, but its [default deserializer](https://github.com/PySport/kloppy/blob/master/kloppy/infra/serializers/tracking/pff.py) uses smoothed geometry and carried event states. This study uses its own raw-visible adapter specifically to preserve separation between observations and supervision. No upstream parser code was copied.
